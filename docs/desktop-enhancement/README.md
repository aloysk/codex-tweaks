# Codex 桌面增强开发准备

本 fork 围绕官方 Codex 桌面应用的日常使用体验展开：外观与阅读布局、可信的即时状态、可恢复的界面增强，以及后续的操作与提醒功能。Windows 是首个实际验收平台；共享 Go 后端和原生双端架构继续遵循上游约定。

当前阶段为**需求与开发准备**。仓库已继承上游代码，本轮新增规划文档，没有实现、安装或启用任何新增增强功能。PRD 中的目标与验收条件不能作为当前产品能力声明。

## 阅读顺序

1. [PRD](PRD.zh-CN.md)：产品范围、模块状态、数据契约、优先级与验收剧本，作为新增功能的需求依据。
2. [开发顺序与验证关口](IMPLEMENTATION.md)：下一阶段从哪里开始、每一步需要取得什么证据。
3. [上游基线与 fork 边界](UPSTREAM.md)：来源、代码落点、工具链现状、更新与安装身份问题。
4. [社区调研](research.zh-CN.md)：候选项目、选择理由与公开证据；保留调研时点，不代替实时兼容性验证。

上游的 [开发约定](../../AGENTS.md)、[现有产品定义](../../PRODUCT.md) 和 [功能包契约](../../Skills/develop-codex-tweaks-package/SKILL.md) 继续适用。若新增功能需要改变既有行为，应先更新相关设计与契约，再按影响范围实现和验证。

## 仓库策略

- `origin` 为自有 fork：<https://github.com/aloysk/codex-tweaks>。
- `upstream` 为原项目：<https://github.com/codex-tweaks/codex-tweaks>。
- 准备文档使用 `docs/desktop-enhancement-plan` 分支，保留主分支的上游基线；后续实现从已确认的准备提交另开功能分支。
- 本阶段只创建宿主 fork。自有功能包先通过本地目录或 ZIP 验证；进入 Git 分发时，按上游规范为每个包建立独立仓库。
- 公开仓库只保存设计、公开源码证据与合成测试资料。实际会话、账号凭据、用户图片和本机诊断原件留在用户设备上。

## 本阶段交付边界

完成项包括：建立 fork 与本地 checkout、记录上游基线、整理调研、形成详细 PRD 和接续计划、检查文档结构与链接、审视范围和一致性、保存文档提交。

下一阶段才开始：针对当前 Codex 版本的连接与注入试验、恢复路径修复、自有功能包开发、产品构建和真实安装测试。文档准备完成不等于这些验证已通过。具体状态以 [开发计划](IMPLEMENTATION.md) 的验证关口为准。
