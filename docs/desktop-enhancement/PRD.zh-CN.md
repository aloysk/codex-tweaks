## 第一章：产品概述

Codex Tweaks Companion 是一款官方 Codex 的本地伴侣控制面板，让开发者管理主题、壁纸和选定增强，并在工作时查看可信状态，而无需迁移会话或更换主工作窗口。

官方 Codex App 始终承担聊天、工具、文件、任务与审批。我们的 fork 演进为独立且精致的控制面板，可选浮动胶囊承担一瞥反馈；桌宠只是未来一种可选呈现。外观设置最终作用于官方 renderer，不能用美化 companion 自己来代替该结果。日常从官方入口正常打开、随后 companion 按已授权偏好工作，是目标体验；目前上游的 CDP 启动限制尚未解决，不能承诺现已无感接入。

### 1.1 差异化对比表

| 功能 | 竞品 | 本产品 | 实现方式 |
|---|---|---|---|
| 外观管理 | 官方 Appearance 已有配色、字体；Dream Skin 聚焦换肤 | 独立面板预览、应用和恢复官方窗口的主题/阅读布局/壁纸 | 优先复用原生能力，再由可恢复 Renderer 包增量增强 |

| 数字的含义 | 社区监控采用各自日志、IPC 或账户来源 | 区分账户额度、任务状态和输出速率，每项可查来源和精度 | 按信号独立验证、失效和降级，不用同一“实时”标签概括 |
| 可持续加入增强 | 独立脚本和功能专用项目各有生命周期 | 只收录有实际用途、可关闭、来源可追踪的少量增强 | 保留 API v3 包机制和来源清单，不建立平台或商店 |

### 1.2 三类用户画像

| 角色 | 核心目标 | 对现有体验最大的不满 | 愿意采用的关键功能 |
|---|---|---|---|
| 长时间使用官方 App 的开发者 | 保留熟悉工作流，调整阅读环境 | 外观和扩展选项分散，缺少直观预览与恢复 | 独立面板修改官方窗口外观，随时恢复 |

| 维护个人工具的开源参与者 | 逐步加入少量实用能力 | 脚本散落，更新后不知哪个失效 | 原生面板统一开关、单包失效隔离、可追溯社区来源 |

这些是设计画像，尚未开展用户访谈。首位验证用户是项目发起人；以五个工作日的使用反馈验证取舍，不收集对话正文，也不从活动量推测情绪或效率。

## 第三章：核心模块详细设计

### 第 3.1 节 连接、启停与恢复

#### a) ASCII 图

```text
+-----------------------------------------------------------+
| 连接与恢复                                                |
| Codex：已发现 · 窗口 1 · 兼容性待检查                      |
| 增强模式：未连接                                          |
| 操作：检查兼容性    查看启动指引                          |
|                                                           |
| 已连接时：停用全部增强    普通方式重开指引                  |
| 错误时：无法确认目标窗口。保持原生界面。  重新检查          |
+-----------------------------------------------------------+

未发现 --> 待连接 --> 检查中 --> 已连接 --> 停用中 --> 已停用
                     |           |                       |
                     +--> 不兼容 +--> 连接中断            +--> 等待普通重开
```

#### b) 交互流程

正常路径：用户打开 companion → 确认官方 App 身份与目标窗口 → 若已有经验证的本机端点则连接，否则显示当前启动条件 → 用户在合适时机保存工作、结束活动任务并按指引自行进入增强模式 → 探测必需能力 → 逐包激活 → 显示已连接。目标行为：companion 伴随官方 App 或登录后台启动时，不自行拉起官方 Codex、不弹出管理窗口或抢焦点；用户显式打开控制面板时显示或复用面板，明确选择启动官方 App 时才执行启动动作。该行为与继承上游现状分别验证。应用不能确认工作状态时不自动重启。启用配置先校验后应用，单包激活失败不使其他已验证包失效。

失败路径一：端口不存在或被占用 → 显示“尚未连接，可继续使用 Codex” → 保持关闭 → 用户处理启动条件后重试；不自行结束占用端口的进程。

失败路径二：目标路径、窗口或能力探测不匹配 → 显示“不支持当前版本或无法确认目标” → 禁止注入 → 可复制兼容性摘要；不能降级为盲目匹配进程名。

失败路径三：停止期间窗口已退出、清理调用失败 → 管理窗口保留“恢复待确认” → 重连同一目标可重试清理，或用户正常关闭后从官方入口重开 → 核验清理结果。仅关闭管理窗口不能显示“调试模式已退出”。

恢复语义分为两个动作、三项状态：**停用全部增强**先停止继续注入，再移除本项目注入效果，允许 CDP 仍存在；**普通方式重开**要求用户自行正常退出并从官方入口打开，核验调试端点不再由目标 App 提供。管理器分别报告“继续注入已停止”“页面清理已验证”“CDP 监听已关闭”，不能仅断开 WebSocket 就声称退出调试模式。检测不到端点时也应结合目标进程身份，不能把连接故障当作完整恢复的证据。

源码复核发现，上游全局停用路径可能忽略 `CleanupAllTargets` 的错误后仍报告 completed；本项目必须保留并呈现清理结果，清理失败归为恢复待确认。上游 `codexLaunchArguments` 当前总是加入 CDP 参数，未来“普通重开”若由宿主实现，需要明确的新启动模式；在此之前只提供官方入口人工重开指引。

#### c) 状态清单

| 状态 | 触发条件 | 视觉标识 | 退出条件 |
|---|---|---|---|
| 未发现 | 无匹配目标 | 灰色“未发现 Codex” | 用户打开官方 App 并重查 |
| 待连接 | 发现目标但无可用端点 | 灰色“未连接”及指引 | 用户启动增强模式 |
| 检查中 | 正在核验身份与能力 | 状态行进度，不遮挡 App | 探测完成或 5 秒超时 |
| 已连接 | 身份与必需能力通过 | 绿色文字及已启用包数 | 停用、断连或版本变更 |
| 不兼容 | 必需能力失败 | 橙色“不兼容”，启用禁用 | 适配更新后重新检查 |
| 连接中断 | 已连接目标消失 | 橙色“连接中断” | 明确重连成功或停用 |
| 停用中 | 用户停用 | 禁用重复点击 | 清理成功或 3 秒超时 |
| 已停用 | 所拥有资源清理确认 | “增强已停用；调试模式仍可能开启” | 用户启用或普通重开 |
| 恢复待确认 | 无法验证清理或普通重开 | 橙色说明与重试 | 获得同目标验证证据 |

#### d) 依赖关系

读取官方进程身份、目标窗口、CDP 可连接性和包能力；写入本项目连接状态、包开关与有限诊断。方向：身份探测 → 兼容性判定 → 包控制器 → 清理结果。源码中既有按进程名终止路径须在首个实现迭代收窄，面向日用版本不自动强杀或终止未知实例。权限失败保持未连接，不提权重试。

#### e) 待决问题

此处未解决：当前 Codex Windows 发行渠道能否支持“从官方入口照常打开后启用增强”的目标。G1 分别验证普通启动、已运行实例和增强启动；若普通启动无法接入，明确标为需要手动准备连接的预览版本。安全默认是人工启动指引，不热改进程、不替换快捷方式、不静默重启。后续只在实证和已有授权内改进体验。

#### b) 交互流程

正常路径：在 companion 外观页选择主题/布局或显式选择本地 PNG/JPEG/WebP → Go 校验本项目设置与素材 → 经验证的适配桥向选定官方 renderer 发送变更 → 官方窗口预览 → 应用后保存 → 收到目标实际应用结果才提示“已应用”。面板缩略图仅是预览，不等同于官方窗口已应用。原生明暗主题变化后重新计算遮罩与可读性，不改写原生配置文件。

失败路径一：非支持图片、文件超过 5 MiB 或任一边超过 4096 px → 内联提示具体限制 → 保持上一次有效状态 → 用户重选。SVG、远程 URL、动画图和目录扫描均不进入此路径。

失败路径二：正文容器无法识别或样式验证失败 → 回滚此次包拥有的修改 → 显示“当前版本暂不支持此布局” → 可继续使用原生布局。回滚只处理本项目拥有的节点和属性，不重置用户原生主题。

失败路径三：设置持久化失败 → 取消“已保存”提示 → 保留用户可见预览并提供取消 → 重试或恢复；下次启动只读取最后一次完整有效配置。

P0 包含可恢复主题、布局与纯色背景，以及能力允许时的本次本地图片预览。**本地壁纸只有在 G2 证明用户显式选图、Go 范围受限的素材存储与 Renderer-only 应用/恢复路径成立后才列入首版持久化交付承诺**；若能力不成立，首版明确省略持久壁纸，不能伪称完整实现或为此默认开启 Node。临时预览明确标识“本次窗口有效”，关闭后不承诺恢复图片。

|---|---|---|---|
| 原生 | 包关闭或恢复成功 | “原生布局” | 选择预览 |
| 待选择 | 本地图片开启但没有有效图片 | 图片占位和选择入口 | 选取通过验证 |
| 预览中 | 未保存的有效设置 | 预览条及取消 | 应用或取消 |
| 已应用 | 设置保存及视觉应用均成功 | “已应用” | 用户修改、停用或适配失败 |
| 读取失败 | 图片不符合约束 | 字段级错误 | 重选或关闭图片 |
| 保存失败 | 本项目存储写入失败 | “未保存” | 保存成功或取消 |
| 适配失败 | 目标容器或验证不通过 | “使用原生布局” | 更新适配并通过探测 |

#### d) 依赖关系

读取原生主题、视口大小、本项目设置和用户主动选中的文件；写入包拥有的样式、背景节点与本项目配置。文件输入只访问用户选择的素材，不读取任意目录。面板持久设置由 Go 管理，Renderer 只接收所需值和经验证的素材引用。面板到包的传输、应用确认及素材路径必须在 G2 实证；当前没有已核定的现成通用设置桥。未核实时不编造 SDK 方法，也不在 C# 或 Swift 中复制配置业务。

### 第 3.3 节 可信状态、输出速率与额度

#### a) ASCII 图

```text
+------------------------------------------------------------+
| 当前任务：运行中 · 已确认          目标：窗口 1 / 已绑定任务 |
| 输出速率：约 24 字符/秒 · 本地观测  最近 5 秒                |
| 账户额度：5 小时剩余 68%           最近读取 14:30            |
| 来源与精度  --> 事件来源、采样区间、源更新时间未知           |
+------------------------------------------------------------+
| 无身份：尚未确认当前任务   无输出：速率不可用                 |
| 断连：数据已失效           部分缺字段：对应项显示未知         |
+------------------------------------------------------------+
```

三个信号独立存在：任务状态回答“现在发生什么”，输出速率描述已观测的生成输出，额度属于账户。界面反应耗时与模型输出速率也分别命名；本项目不承诺提高模型推理速度。胶囊最多显示两项摘要，完整数值与出处留在面板。

#### b) 交互流程

正常路径：确认目标窗口及信号归属 → 读取已验证来源 → 按信号校验身份、字段和时间 → 面板与胶囊显示同一快照 → 用户展开来源/精度。仅订阅或读取已存在数据，不发模型请求、不读写认证文件、不启动另一个 app-server 冒充正在观察官方 App。

失败路径一：缺字段、数值非有限数、无法确定选中任务 → 相应信号显示“未知/暂不可用” → 保留其他有效信号。最近写入日志的任务只能叫“最近观测活动”，不能叫“当前任务”。没有输出既不能推断任务完成，也不能推断待审批。

失败路径二：账户/目标任务变化、多个 active account scope、断连 → 撤下旧身份的数字，清空对应内存快照 → 等到新身份的合法数据再显示。身份仍明确但本地采样过期可保留标陈旧的读数；反复读同一缓存不能伪造源更新。

失败路径三：计数器重置、跨回合或时间不足 → 不显示 token/s → 显示“采样中”或带明确单位的本地观测速率。工具等待、缓存 token、输入 token 与思考耗时不得混入“模型输出 token/s”。数据适配失败不影响官方任务继续运行。

| 信号 | 可接受证据 | 显示规则 | 不足时 |
|---|---|---|---|
| 任务运行/完成/待审批 | 与目标任务匹配、含事件时间的已验证事件或宿主状态 | “已确认”；事件过期或身份丢失即失效 | 日志推测标“推测”；无证据显示未知，不用静默时长推导待审批 |
| 模型输出 token/s | 同一回合单调输出 token 计数及有效生成计时区间 | 标明区间平均值、窗口和来源；不称逐 token 实时值 | 若只有已呈现文本，最多显示“约 N 字符/秒 · 本地观测”，不换算成 token/s |
| 账户额度 | 官方 App 已取得且账户 scope 明确的合法状态 | 实际窗口长度、剩余比例、读取时间；源更新时间缺失明示 | 缺字段未知；scope 歧义或账户变化撤下旧值 |

额度剩余比例按 `100 - usedPercent` 计算并限制到 0–100；无值不是 0。窗口长度与重置时间来自源，不硬编码“5 小时/每周”。速率只有一个累计快照时不可计算；采样间隔至少 1 秒，推荐展示最近 5 秒的有界平均，停止输出时不维持一个“正在生成”的旧数值。

#### c) 状态清单

| 状态 | 触发条件 | 视觉标识 | 退出条件 |
|---|---|---|---|
| 获取中 | 首次读取或有效速率样本不足 | “读取中/采样中”，不造数字 | 合法数据到达或 1 秒后转暂不可用 |
| 已确认 | 来源、目标与字段均通过校验 | 正常文字，来源可查 | 目标变化、过期或断连 |
| 估算/推测 | 已验证的本地观测或有限推断 | 固定显示“约/推测”及单位 | 获得直接证据或推断依据失效 |
| 部分未知 | 独立字段不完整 | 有效项保留，缺项写未知 | 完整快照到达 |
| 陈旧 | 身份明确但本地观测超时 | 灰色旧读数及经过时间 | 同身份的新合法观测或清空 |
| 不可用 | 身份不明、断连、适配失败 | 撤下数字，说明原因 | 来源与身份恢复 |
| 关闭 | 用户关闭某项展示 | 不占胶囊；面板保留开关 | 用户开启 |

这些是字段和显示状态，不要求构建通用状态机框架。

#### d) 依赖关系

Go 统一保存规范化的瞬时状态并向两端提供 Presentation；Renderer 私有字段只存在于窄适配器。额度参考 `usage-overview@2cfbec5563b5e0eb46cd146574d8986a14cc5e45`，其读取 active `rate-limit-status` Query Cache，多账户 scope 歧义时返回 null。参考仅证明一种方法，不证明当前官方版本兼容。账户标识仅用于内存隔离。

额度优先订阅，fallback 每 60 秒最多读一次已有缓存；超过 120 秒未成功采样标陈旧。`observedAt` 只代表本地读取，不能当成 `sourceUpdatedAt`。活动事件采用来源具体的时效规则并在 G3 记录；没有可靠失效/终止信号的源不能持续宣称“已确认运行中”。速率显示刷新上限为 1 Hz，面板和胶囊复用同一采样，不各自读日志或网络。

zcode-monitor 只提供状态呈现、去重和生命周期参考，其 ZCode 数据路径不能直接替换为 Codex 路径后宣称可用。每个新来源都需证明它观察的是用户正在使用的官方 App 及所示范围。

#### e) 待决问题

此处未解决：当前官方版本的选中任务身份、生命周期事件、输出 token 计时区间及账户变化信号能否可靠取得。G3 分别验证；首版可显示明确未知，但状态版发布至少需一个真实可用的任务信号和账户额度样本。精确 token/s 非首版硬承诺，未通过则隐藏该数值并解释原因。

## 第四章：超越竞品的差异化功能

这里的“超越”指本项目希望达到的组合体验，不代表已实现或所有其他项目都缺失这些能力。

### 第 4.1 节 可以验证的恢复

1. 竞品为何未必完整覆盖：基于公开信息的推断，换肤工具的主要边界是移除样式，退出调试模式还涉及进程生命周期；上游现有清理能力不能直接证明后者完成。
2. 本产品如何实现：分别展示界面增强、连接、调试模式三种状态；停用后验证包资源清理，正常重开后验证目标实例。推荐人工正常退出；自动重启只有未来具备准确身份与工作状态后再评估。
3. 交互流程：`停用增强 --> 确认界面恢复 --> 用户正常退出 Codex --> 官方入口重开 --> 核验普通模式`。
4. 风险与应对：验证不可得时保留“待确认”，不自动升级为强杀；管理器崩溃后以安全默认不自动重注入。

### 第 4.2 节 状态有出处，未知可见

1. 竞品为何容易产生缺口：基于公开信息的推断，不同监控项目最初服务单一日志或账户入口，接入桌面多窗口后，数据身份和新鲜度变成额外问题。
2. 本产品如何实现：数据模型带范围、读取时间、源更新时间与证据精度；先分别验证任务信号和账户额度，输出速率有正确计数和时钟才显示。图形和胶囊动画不扩大证据含义。
3. 交互流程：`读取 --> 验证身份与字段 --> 有效值 / 部分未知 / 陈旧 --> 用户查看来源 --> 决定继续工作`。
4. 风险与应对：宿主更新改变结构时隐藏受影响字段，保留原生入口；不退回读取认证文件或内部 HTTP。

### 第 4.3 节 超预期机会

以下三个细节在基本闭环通过后按成本选择，不扩张 P0 承诺：

| 机会 | 结构性原因与实现 | 交互流程 | 风险与应对 |
|---|---|---|---|
| 临时查看原生效果 | 单次开关式工具常缺少对比状态；本项目已有可恢复样式状态 | 按住“原生对比” → 暂停本包视觉 → 松开恢复 | 不改配置；失焦时自动结束对比 |
| 恢复结果小卡片 | 跨生命周期恢复信息通常分散；统一管理器可以汇总 | 停用 → 展示已清理包数与仍待普通重开项 | 只展示已验证事实；未知写待确认 |
| 胶囊的一瞥与收起 | 外置控件容易堆叠信息；共享状态可只取当前最有用的两项 | 开启 → 一瞥状态 → 收为状态点 → 主动返回面板 | 不抢焦点；仍可查“账户级；14:30 读取；源更新时间未知” |

完整结构和源码入口以根目录 `ARCHITECTURE.md` 为准。最大风险仍是官方更新导致私有适配失效：固定已验证版本组合，逐能力探测，单包失败隔离；目标身份失效则停止全部相关操作。普通启动是否可附加、面板设置如何到达 renderer、胶囊如何不抢焦点，必须分别验证，不能用外观 mock 或编译结果替代。

正式功能开发前先满足 `docs/development/runtime-foundation.md` 的基础条件：有界日志及可见写失败、RPC 传输失败传播、配置先保存再生效、普通测试与真实进程/CDP 隔离、取消后不重新激活、有界退出和明确进程归属，以及依赖/开发工具前置检查。这些条件在 PR3 实现并验证；后续功能复用同一基础，不另造日志、状态机或插件框架。

外观包只承担官方 renderer 的效果，不承担 companion 原生界面；Go 拥有设置与动作语义，生成 Presentation 后由两端消费。当前阶段不建立通用状态机、插件平台、远程事件服务或历史数据仓库。资源清单供开发按需查阅，不参与运行时加载。

**可替换技术原则：** 推荐沿用 Go + WinUI/SwiftUI + API v3。可以替换包内部 DOM/CSS 实现和窄适配器，只要数据语义、最少权限、官方工作流、功能独立停用与恢复事实保持不变。CDP 不可用时 companion 仍可提供已验证的外置信息，但主题/壁纸应明确不可用；不能把这种降级宣称为满足完整产品目标，更不能因此改造为新的聊天客户端。

发布前必须隔离安装身份、包 ID、更新源、数据目录、签名/品牌与卸载归属，详情见 `UPSTREAM.md`。现有上游更新配置不能直接作为 fork 的发布配置；本阶段不发布安装器。自有 Git 分发包遵循一包一仓库，包确实需要分发时才建立仓库。

### 7.5 加载状态

小于 200 ms 的本地切换不显示加载动画；超过 200 ms 显示按钮内进度，避免覆盖正文。连接探测上限 5 秒，面板打开上限 2 秒，停止清理上限 3 秒；到时进入可恢复错误状态。额度初次读取超过 1 秒转明确不可用，不保留无限骨架屏。重复动作复用进行中的操作；在应用配置未完成前禁用“应用”，取消入口继续可用。

正文、代码与错误提示按 WCAG 2.2 的对比度标准检查：普通文本至少 4.5:1，大字至少 3:1；不能仅因遮罩大于某值就宣称合格。这里的大字按标准定义，不能自行把字号较大的 UI 文案都算入宽松阈值。参考：<https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html>。高对比度模式默认关闭壁纸；系统减少动画偏好下去掉非必要过渡。首次进入默认原生布局和无背景，用户自行选用。

## 第九章：开发优先级

- **P0 - 没有这个，产品根本无法使用。交付标准：功能可用，不需要完美。** 独立原生 companion 面板承担完整设置；可选、默认关闭的最小浮动胶囊能显示摘要、收起/隐藏并返回面板；一个真实支持版本的安全连接与恢复；面板控制的可恢复主题/阅读布局；任务状态、输出速率和账户额度的来源/精度展示及诚实未知；有限配置与诊断。状态版至少验证一个真实任务信号与账户额度样本，精确 token/s 和持久壁纸未过关时明确不提供。普通启动仍需手动准备时只能标注预览限制。
- **P1 - 没有这个，用户第一次体验后不会回来。交付标准：功能完整，体验有连续性。** 在已验证连接机制内减少日常启动摩擦；本地壁纸持久化；胶囊多显示器位置恢复与通过目标身份验证后的窗口跟随；补足来源允许的输出速率和任务切换语义；完善常用主题与版本覆盖。无法满足正常启动目标时明确剩余限制，不能以静默重启完成。
- **P2 - 有了这个，用户会把产品推荐给别人。交付标准：稳定且有辨识度。** 从社区精选的去重提醒、演示/专注模式、原生效果对比、更多主题与胶囊停靠；设置导入导出、有限性能诊断，以及用户主动操作的官方速度/Fast 模式、插件/Skills/MCP 入口。每项需独立用途与验收，不建立商店或历史分析中心。
- **P3 - 有了这个，一部分用户会付费或强烈倡导。交付标准：精致且有完整文档。** 桌宠作为已验证状态的可选表现，以及有真实需求的语音、硬件入口和更多平台组合。当前无收费、账户系统或云同步计划；“付费”只是该优先级的价值尺度。

## 第十章：性能指标

以下全部是**设计目标，尚未实测**。固定同一机器、同一官方版本、同一会话和窗口尺寸，增强关闭作为基线；记录硬件与系统版本。启动类至少重复 10 次，交互类至少 100 次；首轮样本用于校准目标，调整需保留理由。模型首字或生成速度属于外部依赖，不作为本项目提升承诺。

| 指标名称 | 目标值 | 测量方法 | 劣化阈值 |
|---|---:|---|---:|
| 已运行 companion 打开面板至可交互 | p95 ≤ 200 ms | 原生事件时间戳/ETW 与录屏核对 | p95 > 500 ms |
| 胶囊数据到达至呈现 | p95 ≤ 150 ms，刷新 ≤ 1 Hz | 共享快照时间戳与原生呈现记录 | p95 > 500 ms 或持续 > 1 Hz |
| 面板外观命令至官方窗口首帧可见 | p95 ≤ 250 ms | Go 命令与 renderer requestAnimationFrame/确认标记 | p95 > 600 ms |
| 全部首版包激活耗时 | p95 ≤ 1000 ms | CDP 已连通后至所有包完成，不计 App 启动 | p95 > 2000 ms |
| 停用至所有自有资源清理 | p95 ≤ 1000 ms | 资源登记表、DOM、监听与计时器检查 | > 3000 ms 进入恢复待确认 |
| 闲置 CPU 增量 | ≤ 1 个百分点 | 同场景 10 分钟平均，增强开关对照 | > 2 个百分点 |
| 内存增量 | ≤ 120 MiB | 全部相关进程 working set 中位数，10 分钟采样 | > 200 MiB |
| 长会话滚动帧耗时增量 | p95 增量 ≤ 3 ms | 同一 500 条消息测试会话，60 秒 trace | p95 增量 > 8 ms |
| 页面主线程新增长任务 | 60 秒内 ≤ 1 个超过 50 ms 的任务 | Performance trace 按本项目脚本归因 | 60 秒内 > 3 个 |
| 静态图片输入限制 | ≤ 5 MiB 且单边 ≤ 4096 px | 导入前大小校验、解码后尺寸校验 | 任一超限拒绝，不降级绕过 |
| 本地额度 fallback 轮询频率 | 最多 1 次 / 60 秒 | 仅计兜底定时读取；事件订阅刷新不计为轮询 | 超过 2 次 / 60 秒 |
| 连接中断后面板与胶囊撤下失效数字 | ≤ 2 秒 | 断开目标后录屏与共享状态日志比对 | > 5 秒 |
| 胶囊被动更新引发的焦点切换 | 0 次 / 100 次更新 | 官方输入与审批期间检查前台窗口和输入内容 | 任意 1 次即失败 |
| 启停循环资源增长 | 20 次后自有 DOM/监听/计时器归零 | 激活/清理登记及堆快照对照 | 任一持久增长或残留即失败 |

测试会话用合成内容，不把真实用户对话写进 fixture。超过劣化阈值先关闭受影响包并定位；性能目标调整须区分机器基线与实现缺陷。不能用禁用 GPU、缩减原生内容或更改历史来满足指标。

## 第十一章：开发者交接说明

### a) 实现顺序建议

你应先读取根 `AGENTS.md`，再按 `CONTRIBUTING.md` 做任务范围内的开发检查；用 `ARCHITECTURE.md` 找源码职责，用 `DESIGN.md` 实现视觉，用 `docs/resources/README.md` 和 manifest 只取当前任务相关参考。当前交付范围是文档与基础设施，不提前实现本章功能。

进入实现阶段后，你按以下结果推进，不为关口另建流程平台：

1. **G1：目标与恢复。** 先做合成进程/renderer 测试，再在空闲测试实例验证。证明普通启动与增强启动的真实差异、目标身份、清理结果和人工普通重开；有阻碍就保留预览限制，不能强杀用户进程。
2. **G2：面板驱动的外观。** 先做一个窄的 Go 设置/应用确认契约与原生外观页，使主题/布局真实作用于官方窗口且可恢复。再验证本地图片的最少权限选择和持久化；没通过就只交付已验证部分。
3. **G3：可信信号。** 分别核验任务状态、速率和额度。至少一个真实任务信号与账户额度样本通过，再称状态版；token/s 无可靠计数与时钟就不给这个数字。完成规范化和失效测试后复用至视图。
4. **G4：完整 companion 闭环。** 完成原生面板导航与最小胶囊，验证焦点、屏幕工作区、配置、恢复、性能和首次使用；桌宠与更复杂停靠不进入这一轮。首个可安装 fork 还必须通过身份隔离与实际安装验证。

你可以先在合成数据下制作面板和胶囊视觉原型，以尽早评估设计；原型必须标示样例数据，不算 G2/G3 的真实接入证据。每轮只增加一个可验收能力，未执行项保持“未执行”。

### b) 最可能导致返工的三个决策

| 决策 | 安全默认选择 | 改变方向的信号 |

### d) 已知的未知项

- 当前记录的 Codex Store `26.930.2377.0` 只是检测快照；普通启动可连接性、私有 UI 结构及后续版本兼容均未验证。你必须记录实际目标版本。

### e) 验收剧本

**验收剧本 1：正常启动与恢复。** 你在已记录版本的 Windows 11 x64，从官方入口打开空闲测试实例，再打开 companion。无可用端点时必须说明当前限制而不自动重启；按人工指引准备后启用和停用增强。保留合成草稿，核对内容与任务没有变化，并分别以目标身份、资源计数和监听检测验证继续注入已停止、页面清理、用户普通重开后的 CDP 关闭。断开 WebSocket 不能作为最后一项证据。

**验收剧本 2：面板控制官方外观。** 你在 companion 选择主题和阅读布局，观察官方合成长会话、代码、差异与审批区域实际变化，再取消预览和恢复。若图片能力已过关，加入合法图片、超 5 MiB 和伪装类型样本。错误时保留上次设置，不能只改变面板缩略图就提示已应用。用前后截图、配置、应用确认和 100%/125%/150% DPI 记录验证。

**验收剧本 3：状态、速率与额度真实性。** 你对照实际来源，再用合成 fixture 覆盖缺字段、任务切换、账户歧义、断连、计数器重置和时间不足。任务与账户不串值；推测保留标签；字符速率不称 token/s；缓存读取不冒充源更新时间；未知不是 0。以映射测试、来源摘要和面板/胶囊画面验证，fixture 不能替代真实接入样本。

**验收剧本 4：面板、胶囊与输入。** 你保留官方多行草稿，开启胶囊、收起/展开、反复打开面板，执行 100 次被动更新，再改变 DPI 和断开显示器。应只有一个面板，胶囊保持可见工作区，更新不抢焦点或改草稿；用户主动打开面板才切换焦点。覆盖中文 IME、审批窗口与键盘操作，用前台窗口记录、逐字符草稿对照和录屏验证。

**验收剧本 5：失效隔离与资源。** 你对自有包连续启停 20 次，制造不兼容与清理失败，检查其他功能和官方 App 继续可用，恢复失败不报告完成；再在相同合成长会话测 60 秒滚动和 10 分钟闲置，将第十章目标与实际结果逐项记录。以 trace、资源计数、包权限和版本矩阵验证。后续可安装交付另按 IMPLEMENTATION 的发行条件验证安装/更新/卸载隔离，不能从上述开发测试外推。
